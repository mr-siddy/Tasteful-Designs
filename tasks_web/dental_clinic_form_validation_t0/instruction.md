The appointment request form on our page is letting anything through. Someone can
land on the site, scroll to "Tell us what you need and we will call you back",
click the send button without typing a single character, and the form still
swaps straight over to the thank-you panel — which then greets them by name with
a blank space where the name should be, and lists an empty visit type. The front
desk gets a request with no way to call anyone back. The same thing happens with
a half-typed email address like `doug.whitfield.at.kestrelmail` or a phone number
that is only four digits long: the page accepts it and says thank you.

What should happen is that an incomplete or obviously wrong request never gets
that far. If the name, email address, phone number or reason for the visit is
missing, or the email address is not a real address, or the phone number is too
short to ring back, the page should stay on the form, keep everything already
typed exactly where it is, and show a short message next to each field that needs
attention so the visitor knows what to fix. Someone using a screen reader should
be able to tell which fields are the problem ones, not just hear that something
went wrong. Once every one of those details is filled in properly, sending the
request should confirm it the way it does today.

Nothing else about the page should change — same sections, same copy, same
fields in the same order, and the confirmation panel itself stays exactly as it
is for requests that are genuinely complete.
