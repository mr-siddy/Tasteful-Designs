Our sales team is getting walkthrough requests they can't do anything with. The
"Book a walkthrough" form near the bottom of the marketing site takes whatever
it is given: click the button with every field still blank and the page swaps
straight to the green "your walkthrough request is in" confirmation, as though
a real request had been booked. Same thing if someone types `renata@` into the
work email, or puts `a dozen` in for the number of technicians — confirmed,
booked, gone. Nothing on screen ever tells the visitor that something was
wrong, so half of what reaches the solutions engineers has no name on it and no
address anyone can reply to.

A submission should only go through once it is actually usable. If the visitor
has left their name blank, or the work email is not a real address, or the
technician count is missing, zero, negative or not a number at all, the button
should refuse it: the visitor stays on the form and the field that needs
attention shows the reason underneath it. They should never see the
confirmation panel for a submission that was refused. Once they fix what was
flagged and submit again, the message under a field that is now fine should be
gone and the confirmation should appear exactly the way it does today.

The optional "what are you running today" note stays optional. Leave the rest of
the page alone — the same sections, copy, prices and layout, and the form should
keep the same fields, labels and button it has now.
