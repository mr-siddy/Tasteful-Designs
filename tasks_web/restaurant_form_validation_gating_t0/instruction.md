Odalys is getting Long Table requests she can't do anything with. The private
dining form on the site takes whatever it is handed: click "Send the request"
with every field still blank and the panel swaps straight to the green "Your
Long Table request is in" confirmation, as though a real party had been booked.
Same thing if someone types `odalys@` into the email, or puts `a dozen` in for
the number of guests, or never picks a seating at all — confirmed, gone. Nothing
on screen ever tells the visitor that anything was wrong, so a third of what
lands in the events inbox has no name on it, no address anyone can reply to, and
no idea how many people are coming.

A request should only go through once we could actually act on it. If the name
is blank, or the email is not an address we could write back to, or the party
size is missing, isn't a whole number, or falls outside the six-to-sixty the
table seats, or no seating has been chosen, then sending should be refused: the
visitor stays on the form and the field that needs attention shows the reason
underneath it. They should never see the confirmation panel for a request that
was refused, and a field that is fine shouldn't be marked as though it weren't.
Once they fix what was flagged and send again, the messages should be gone and
the confirmation should appear exactly the way it does today.

The "anything we should know" note stays optional — a request with it left empty
is still a good request. Leave the rest of the page alone: the same sections,
copy, hours and prices, and the form should keep the same fields, labels,
seatings and button it has now.
