The front desk is getting intro-session bookings nobody can act on. The "Book an
intro session" form near the bottom of the site accepts absolutely anything:
press the button with every box still empty and the panel flips straight to the
green "you're booked in for an intro session" confirmation, as though a real
booking had been made. Same story if someone types `alma@` into the email, puts
`5550` in for a mobile, or never touches the start-week dropdown at all —
confirmed, booked, gone. Nothing on the screen ever tells the visitor that
something was missing, so a third of what reaches the teachers has no name on
it and no number anyone can call back.

A booking should only go through once we could actually act on it. If the
visitor has left their name blank, or the email is not a real address, or the
mobile number is missing or too short to dial, or they have not chosen a start
week, the button should refuse it: they stay on the form and the box that needs
attention explains what is wrong underneath it. They should never see the
confirmation panel for a booking that was refused. Once they fix what was
flagged and press the button again, the message under a box that is now fine
should be gone and the confirmation should appear exactly as it does today.

The "anything we should know?" note stays optional. Leave the rest of the page
alone — the same sections, copy, classes and prices — and the form should keep
the same fields, labels, dropdown options and button it has now.
